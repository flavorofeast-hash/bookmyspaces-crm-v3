# RC2 Phase 2 — Lead Workspace Audit

**Date:** 2026-08-02
**Mode:** Read-only investigation. No code changed. No commits.
**Scope:** What already exists in the codebase that could be linked into `/dashboard/leads/[id]` (currently a pure viewer — name/phone/email/company/location/dates/notes, no actions, no links to any other module) instead of being rebuilt.

**Method note:** two other screens already assemble most of these features around the same `leads` row — `/customers/[id]` (Customer Profile: lifetime value, opportunity score, timeline, proposals list, full AI Operator Assistant panel) and `/kanban` (drag-drop stage board with a lead detail side-panel: WhatsApp click-to-chat, Create Proposal link, stage quick-move, follow-up scheduling, notes, AI summary, activity feed). Most of this audit is "already built and wired on one of those two screens, not on Lead Details" rather than "doesn't exist anywhere."

# Executive Summary

**1. Which features already exist?**
Nearly everything the mission asked about already exists somewhere in the codebase: the full proposal lifecycle (create/edit/view/PDF/share/email/invoice/payment/receipt/booking-confirmation), site visit scheduling with its own service and API, a full reservation module (creation, management, detail page, calendar, availability), a follow-up system (schedule/note/complete/send, with a cron job), a unified cross-source Timeline that already merges chat/WhatsApp/email/activity/proposals/payments/reservations/AI-interactions into one feed, a real WhatsApp conversation inbox with send capability, real email infrastructure with 5 templates and delivery logging, validated lead-stage transitions covering "won"/"lost" as regular stage moves, and a working AI layer covering qualification, package recommendation, proposal drafting, and follow-up suggestions. The only two genuinely new things (not just wiring) are a freeform email composer and an "assign owner" control.

**2. Which features are implemented but hidden?**
Two screens carry almost the entire feature set that Lead Details is missing: `/customers/[id]` (Timeline, Proposals list, Lifetime Value, Opportunity Score, the full 8-action AI Operator Assistant + Event Sales Advisor) and `/kanban` (stage transitions, WhatsApp deep-link, Create Proposal link, follow-up scheduling, notes, AI summary). Both are fully built and live; Lead Details simply doesn't call into either of them. The site-visit-to-timeline connection is also implemented but effectively hidden — it exists as an untyped `activity_logs` row rather than a labeled "visit" entry, so it's easy to miss even where the Timeline is already shown.

**3. Which features only require wiring together?**
The overwhelming majority: stage transitions (`PATCH /api/leads/[id]/stage`, already validated, already used by Kanban), the unified Timeline (`GET /api/customers/[id]/timeline`, one fetch call), the Proposals list (`GET /api/proposals?lead_id=`), the AI Operator Assistant panel (`POST /api/customers/[id]/ai`, already a self-contained component), WhatsApp click-to-chat (a plain `wa.me` link, no API call needed), follow-up scheduling/notes (`POST /api/followups`), and every proposal-flow action (PDF/share/email/invoice/payment/receipt) once a proposal is linked. None of these need new backend logic, new database tables, or new AI prompts — they need buttons, links, and fetch calls added to one page.

**4. Which features truly do not exist?**
Two: a generic, freeform "compose an email to this lead" screen (only fixed-template proposal/invoice/payment/booking emails exist — there's no free-text composer anywhere), and any UI for setting `leads.assigned_to` (the column and API support exist, but no picker/dropdown was found in any page). A third item is a soft gap rather than a missing feature: reservation data depends on migration 012, which was last confirmed **not applied** to production — the code path degrades gracefully (already handled by `getCustomerTimeline()`), but reservation history won't actually populate on Lead Details until that migration's live status is re-verified.

**5. Smallest implementation plan to turn Lead Details into a full Lead Workspace:**
In order of leverage-to-effort:
1. Fetch and render `GET /api/customers/[id]/timeline` on Lead Details — one API call already returns the merged history across every channel (chat, WhatsApp, email, activity, follow-ups, proposals, payments, reservations, AI interactions). This alone answers most of "what's happened with this lead."
2. Fetch and render `GET /api/proposals?lead_id=` — a short proposal list (reuse the exact rendering already written in `/customers/[id]`).
3. Add stage-transition controls calling `PATCH /api/leads/[id]/stage`, filtered through `VALID_TRANSITIONS` (reuse the exact logic already written in `/kanban`) — this single addition covers Change Stage, Mark Won, and Mark Lost simultaneously, since those are all just target stages.
4. Add a `wa.me` deep-link button (zero API calls, copy the one-line pattern from `/kanban`) and a link to `/whatsapp` (optionally extended with a `?phone=` filter, a small addition to that page).
5. Mount the existing `AIAssistantPanel` component (or extract it to a shared location and import it) from `/customers/[id]` as-is — it already takes just a `customerId` prop.
6. Add a "Schedule Visit" link to `/visits/new?leadId=...` and a "Create Proposal" link to `/proposals/new?lead_id=...` (both pages already accept a pre-fill lead id via query params, per the pattern `/kanban` already uses).
7. Only after the above: consider the two genuine gaps (an "Assign Owner" dropdown writing `assigned_to` via the existing `PATCH /api/leads`, and a freeform email composer) as separate, smaller follow-up tasks — neither blocks the rest of the workspace.

Every step above reuses an existing, already-tested endpoint or component; none requires a new database table, new migration, or new AI prompt.
